## コンセプト

モバイル向けの転売商品探索サイト。
Twitterで情報を集めていたのを全て統合し、自分では見つけられない商品も先回りして見つける。
全ての転売ツイッタラーを上回る商品一覧と予想精度を目指す。
**品質ベンチマーク:** @pokecachan / @oroshinohito が扱う商品の精度を正解セットとし、MarketLens 単独の選定精度を彼らと同等まで引き上げ、**最終的には先回り・網羅・独自厳選で追い越す**（[ダイジェストUIプラン](superpowers/plans/2026-06-23-marketlens-digest-bundles-ui.md) §1c）。
AIが全面的に主導し、商品の発見・判定・予測・説明・対話の全てを担う。

## 1. ソースアーキテクチャ（超大規模）

### 設計思想

固定URLを巡回するだけではなく、AIが自律的に「どこを見るべきか」を判断して
商品を発見する。人間の転売ヤーが見つける前に先回りする。

### レイヤー構造

#### Layer 0: Market Mapper（週1回, Gemini 2.5 Pro）

AIが「まだ監視していないが監視すべきソース」を自力で発見する。
新しいアカウント、新サイト、新コミュニティを検出し、source-configに自動追加する。

#### Layer 1: 探索エージェント（Discovery Agent, 毎回実行, Gemini 2.5 Pro）

現在の商品リストと最近のトレンドを入力として、
「次にどこを見るべきか」「どんな検索クエリを投げるべきか」を決定する。
予測型探索も行う（例:「ポケカ新弾発表から2週間後に抽選が始まるパターン」）。

#### Layer 2: 収集エンジン（Collector）

Discovery Agentが指示したURL + 固定ソース200件を巡回する。

手段:
- Jina Reader（テキスト系サイト）
- Playwright（JS重いサイト）
- Yahoo!リアルタイム検索（X/Twitter代替、バズ検出）
- メルカリスクレイプ（価格観測、急上昇検出）

#### Layer 3: 抽出+スクリーニング（Flash-Lite）

生データから商品情報を構造化し、明らかなゴミを除外する。
「これは商品名か？」「転売対象カテゴリか？」のYes/Noを高速に判定する。

#### Layer 4: 本判定（Gemini 2.5 Pro）

スクリーニング通過した商品を「転売のプロ」として判定する。
利益予測レンジ、なぜ売れるか、類似実績、いつ何をすべきか、リスクを出力する。

#### Layer 5: ブリーフィング生成（2.5 Flash）

T1/T2の商品情報を元に、俯瞰タブに表示する日次レポートを自然文で生成する。

#### Layer 6: 競合監視

大手転売情報アカウント20件を常時監視し、
彼らが推す前に同じ商品を見つけていれば「先回りできている」と判定する。
見逃しがあればソース追加のトリガーにする。

### 固定ソース200件の構成

| カテゴリ | 件数目安 | 例 |
|----------|---------|-----|
| 公式ストア/発売カレンダー | 30 | ポケセン、バンダイ、タカラトミー、あみあみ、スクエニ、カプコン、セガ、コトブキヤ等 |
| 一番くじ/抽選系 | 15 | 1kuji.com、セブンネット、くじ引き堂、各コンビニ |
| フリマ/オークション観測 | 20 | メルカリ各カテゴリ、ヤフオク、ラクマ |
| X情報系(Yahoo!リアルタイム経由) | 50 | 転売系・速報系・公式アカウント |
| ニュース/レビューサイト | 30 | hobby watch、電撃ホビー、4Gamer、ファミ通等 |
| コミュニティ(公開) | 20 | Reddit、5chまとめ、note等 |
| 価格比較/在庫監視 | 20 | 駿河屋、ヨドバシ、Amazon価格追跡 |
| AI自律追加枠 | 15+ | Discovery Agentが見つけた新ソース |

### X/Twitter情報の取得

X APIは使わない。Yahoo!リアルタイム検索で代替する。

バズ商品の検出:
- 「即完売 OR プレ値 OR 争奪戦」等の検索で1000いいね超えを検出
- 転売アカウントだけでなく一般層で話題になっている限定品を拾う

転売アカウント:
- AIが有力アカウントを自動発見・追加する
- 初期は手動で10〜20アカウントを設定

### 速度（先回り）

| アプローチ | 方法 |
|-----------|------|
| 高頻度巡回 | 重要ソースは1時間おき、他は6時間おき |
| イベント駆動 | 発売日1週間前に関連ソースの巡回頻度を自動UP |
| 差分検出 | 前回と比較して新情報だけ処理 |
| AI予測巡回 | 「来週新弾発売→今週メルカリで予約相場が立つはず」→ 先にメルカリ巡回 |

### フリマデータ

| プラットフォーム | 取得対象 | 優先度 |
|----------------|----------|--------|
| メルカリ | 売却済みデータ（実売価格）+ 出品中（参考価格） | 高 |
| Yahoo!フリマ | 売却済みデータ | 高 |

急上昇検出: カテゴリ別に過去7日と今日の出品価格を比較し、上昇率20%以上を自動抽出する。

## 2. AI設計

### 全体にAIが入る

AIはラベルを貼る道具ではなく、全工程を主導する存在。
商品の発見・判定・説明・予測・対話の全てにAIが入る。

### Geminiモデル使い分け

| レイヤー | モデル | 役割 |
|----------|--------|------|
| スクリーニング | gemini-3.1-flash-lite | 商品か？転売対象か？のYes/No。全件処理 |
| 本判定 | **gemini-2.5-pro** | 利益出るか、なぜ、いくら、いつ動くべき |
| 深掘り | **gemini-2.5-pro** | T1/T2の類似実績比較、詳細分析 |
| ブリーフィング | gemini-2.5-flash | 俯瞰タブの日次レポート生成 |
| 探索指示 | **gemini-2.5-pro** | 次にどこを見るべきかの判断 |
| Market Mapper | **gemini-2.5-pro** | 新ソース発見（週1回） |
| チャット応答 | gemini-2.5-flash / pro | ユーザーの質問に回答（オンデマンド） |

### 本判定プロンプトの核心

AIは「日本の限定品転売市場で年間売上1000万円のプロの目利き」として判断する。

判断基準（優先度順）:
1. 供給制約: 限定数、抽選制、受注生産、店舗限定
2. 需要の確実性: ファン層の規模×熱量
3. 過去実績: 同シリーズ・同ジャンルの前例
4. タイミング: 初動利益か寝かせ必要か
5. リスク: 再販、在庫だぶつき、値崩れ

出力:
- tier: T1(即買い)/T2(要検討)/T3(様子見)/HOLD(見送り)
- profit_prediction: { min_jpy, max_jpy, confidence(1-5), basis }
- reasoning: 3文以上の判断理由（具体的な数字や実績を含める）
- similar_products: 類似商品の売却実績
- action: いつ何をすべきか
- urgency: immediate/this_week/next_week/watch
- risk_factors: リスク要因

### Tier定義

- T1: 即行動。利益+5,000円以上がほぼ確実。過去実績あり
- T2: 要検討。利益出る可能性が高いが不確実要素あり
- T3: 様子見。利益出るかもしれないが根拠薄い
- HOLD: 見送り。利益出ない or リスクが高い

### 予測→実績の学習ループ

1. 商品発表即で予測を出す（データ不足時は信頼度を下げて表示）
2. 発売後にメルカリ/Yahoo!フリマの実売データを取得
3. 自動で精度スコアを計算
4. カテゴリごとの傾向パターンを蓄積して次の予測に反映

### コスト

月額¥0を目標（Gemini無料枠内）。
Pro: 5 RPM制限あり → 1日8回実行で分散処理。

## 3. UI/UX設計

### 基本方針

- モバイルファースト。PCでも見れるがモバイルが最優先
- ダーク一択（ライトモードは作らない）
- SVGアイコン（絵文字は一切使わない）
- Apple的なミニマルデザイン

### 画面構成

2タブ + AIチャットオーバーレイ:

```
[レイヤー構成]
L5: AIチャットオーバーレイ（右下FAB → 下からシート）
L4: 下タブナビ: [俯瞰(左)] [商品(右)]
L3: コンテンツ（スクロール領域）
L2: ヘッダー（最小限）
L1: 背景
```

### 俯瞰タブ

AIが自然文で「今何をすべきか」を語る画面。
数字やリストを読ませるのではなく、AIが消化して伝える。

構成:
- 今すぐやるべきこと
- AIの推薦理由
- 市場で起きていること（Xバズ、メルカリ急騰等）
- 先の予定（来週以降で頭に入れておくべきこと）

載せないもの: システム状態、判定率、技術的な数字

### AI文体

- 丁寧語
- 文として完結させる（体言止め禁止）
- 友達口調にしない
- レポート調にしない
- 普通に読める自然な日本語

例:
```
明日ROBOT魂ズワァースの予約が始まります。
このシリーズは過去3年で7割以上がプレ値をつけていて、
+9,000円前後の利益が見込めます。
プレバンで10時から受付開始なので、忘れずに確保してください。
```

### 商品タブ

#### 横タブ（カテゴリ）

```
[全体] [ポケカ] [くじ] [フィギュア] [限定品] [その他]
```

横スクロールで切り替え。
「全体」はAI優先順で全カテゴリ混合表示。
各カテゴリタブはそのカテゴリだけ表示。

#### 縦セクション（期限）

```
━━ 今日・明日 ━━
  (締切/開始が48時間以内)
  常に展開

━━ 今週 ━━
  (3日後〜今週末)
  常に展開

━━ 来週 ━━
  (来週月〜日)
  デフォルト展開。件数多ければ上位5件+「他N件」

━━ 再来週以降 ━━
  (2週間以上先)
  デフォルト折りたたみ

━━ 日付未定 ━━
  (AI判定済みだがイベント日不明)
  一番下。折りたたみ
```

各商品は「最も近いイベント日」のセクションに配置される。

#### セクション内の並び順（AI優先順）

スコア計算:
```
score =
  利益確度 (0〜40: sold実績=40, listing参考=20, AI予測のみ=10, 不明=0)
  + 利益額 (0〜30: +¥10k以上=30, +¥5k〜=20, +¥2k〜=10, それ以下=5)
  + 緊急度 (0〜20: 今日=20, 明日=15, 今週=10, 来週=5, それ以降=0)
  + AI信頼度 (0〜10: Gemini判定済み=10, deterministic=3, 未判定=0)
```

#### カード: 2行コンパクト

```
┌─────────────────────────────────────────┐
│ ROBOT魂 ズワァース         +¥9,000   ▲ │
│ 予約明日 │ 初回プレ値率72%  確度●●●○  │
└─────────────────────────────────────────┘
```

1行目: 商品名 + 利益 + 方向
2行目: 次イベント + AI理由1行 + 確度ドット

#### タップ展開（詳細）

- AIの見解（2〜4文の自然文）
- 利益予測レンジ + 根拠
- 具体的アクション（いつ何をすべきか）
- 類似商品の売却実績
- リスク要因
- [この商品についてAIに聞く] → チャット起動

### 利益表示ポリシー

| データ | 表示 | 色 |
|--------|------|-----|
| 売却済み実績あり | +¥X,XXX | 緑 `#30d158` |
| 出品中価格のみ | +¥X,XXX 参考 | 黄 `#ffd60a` |
| データなし | 表示しない | — |

### 表示対象（厳格）

表示する:
- AI判定済み（Gemini）かつ T1/T2/T3
- 名前が正常（4〜90文字、HTML断片でない、説明文でない）
- 日付あり or AI判定で重要と判断されたもの

表示しない:
- deterministic_pending（AI未処理）で有用な情報がないもの
- HOLD
- 名前がHTML断片 or 説明文風
- 想定利益¥1,000未満
- 仕入れ額¥50,000超
- 締切から1週間以上経過

### デザイン言語

## 4. 商品構造

### 商品群が主役

商品群（productGroup）が最小表示単位。個別商品は群の中に紐づく。

### カテゴリ

固定: ポケカ / くじ / フィギュア / 限定品 / その他
AI分類で自動振り分け + キーワードマッチ補助。

### ポケカの扱い

- 最優先。スコアブーストで自動的に上位に来る
- BOX単位で利益計算

### 日付

- 抽選: 終了日が重要（カウントダウン対象）
- 販売: 開始日が重要（カウントダウン対象）
- 3つ保持: 抽選期間、発表日、発売日

---

## 5. 技術・運用

### コードベース

- UIは vanilla HTML/CSS/JS（ビルドツールなし）
- パイプラインは Node.js scripts/*.mjs
- データは data/marketlens.snapshot.json

### 実行環境

当面はGitHub Actionsで頻度を上げる（8〜12回/日）。
速度不足ならRailway等のクラウドに移行する。

### ホスティング

GitHub Pages（現状維持）。PWAは後で対応。

### 安全ルール（維持）

- 価格正本/BuyLineの安全境界は維持
- browser_observed_candidateの直接昇格禁止は維持
- AI推定利益を確定利益として扱わない
- 公式 > 実売データ > X > ブログ/ニュース の優先順位

# MarketLens 商品群主役 完成実装プラン

> **実行規則:** 既決事項の実装に限定する。各変更は回帰を先に失敗させ、最小修正で通す。価格 safety、BuyLine、既存の決定論価格昇格境界は変更しない。

**Goal:** MarketLens を、全商品を商品群正本へ収容し、Gemini 判断と決定論価格を安全に分離した、商品群主役の市場判断 UI として完成させる。

**Architecture:** `normalizedProducts` を必ず1つの商品群へ収容し、Gemini 判断が成立した群だけを昇格候補にする。AI 未判定、同定不良、event 不明、モデル間・抽出間不一致は `HOLD + requiresHumanReview=true` に倒す。価格・利益・BuyLine は `productKey` で既存決定論データへ表示時に結合し、AI judgment には入れない。

**Tech Stack:** Node.js ESM scripts、静的 HTML/CSS/JavaScript、snapshot JSON pipeline、Gemini API、GitNexus、回帰スクリプト

---

## 完了監査の対象

- 商品群が正本単位であり、全 `normalizedProducts` が重複なく1群へ所属する
- 商品群は複数 member と複数 event を保持できる
- 抽選は終了、販売・再販・受注は開始を別の重要時刻として保持・表示する
- Tier は「今見る順番」として表示される
- Gemini が identity / membership / event / Tier / reason / uncertainty を判断する契約を持つ
- Gemini 以外の real AI provider を使わない。複数モデルの provenance と不一致を保持できる
- 公式 > X > 記事 > 未確認の証拠優先順位を保つ
- X は注目度材料として保持し、裏付けなしに全件を急上昇扱いしない
- 信頼性が弱い群は前面昇格せず、HOLD として圧縮する
- 確認済み決定論価格だけで商品群の利益表示を作る
- `browser_observed_candidate`、未昇格 `jpyCandidate`、AI / heuristic price を確定利益へ使わない
- 全件へ到達できるが、低優先度は折りたたむ
- 旧 candidate-first の「急上昇」「外れた候補」「次に見る」等を主画面から退ける
- モバイル幅で商品名、Tier、利益状態、イベント種別、HOLD理由を判断できる
- snapshot / history / public-history / public-share が同じ契約へ同期される
